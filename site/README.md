# QueryWitness example explorer

A static, read-only developer/research surface generated from actual benchmark
artifacts. It has no backend, remote dependencies, arbitrary SQL input, or query
execution. All results and downloads are pre-rendered; JavaScript only selects
which family to show. Without JavaScript, every family is visible.

## Build

From the repository root, after running the documented benchmark:

```sh
python scripts/build_demo.py
python -m http.server 8766 --directory site/dist
```

Open `http://localhost:8766`. The build defaults to `benchmarks/v1/summary.json`,
its sibling witness bundles, and `src/querywitness/data/catalog.json`. Options:

```sh
python scripts/build_demo.py --benchmark /path/to/run --output /path/to/new/output
```

The builder uses only the Python standard library. It checks the catalog digest,
recorded witness checksums, successful mismatch status, query correspondence,
required bundle files, and aggregate detection/evaluation counts before writing.
It preserves downloaded source bytes. It does not execute SQL or independently
verify benchmark methodology; replay the witness files with the CLI for that.
Missing witness families remain explicitly unavailable. No data is synthesized.

Only an output directory already marked as generated by this script can be
replaced. The build refuses destinations that contain its source inputs. Do not
store hand-edited files in `site/dist`: a successful rebuild replaces that entire
generated directory. Publish the contents of `site/dist`, not the source template.
The source template intentionally contains build tokens.

## Checks

Install the project and its SQLGlot dependency first, then:

```sh
python -m unittest discover -s site -p 'test_*.py' -v
node --check site/app.js
node --test site/test_app.cjs
```

Tests generate a genuine temporary one-family benchmark outside the repository.
They cover exact downloadable source bytes, missing inputs/witnesses, checksum
and catalog drift, output preservation, and template completion. Tests never
replace the production benchmark. The Node tests exercise selection, deep links,
browser history, focus and announcements against a small DOM test harness.

Visual/accessibility considerations: responsive one- and two-column layouts,
scrollable narrow tables, keyboard focus, skip link, hash-addressable families,
selection announcements, reduced-motion support, no color-only result encoding,
and print styles. Inspect desktop and mobile rendering before publication.

The benchmark scope is development-set synthetic coverage. Seed repeats are not
independent tasks. A row-1-minimal label means no schema-valid single-row deletion
preserves the successful mismatch; it does not mean globally minimal.

The supplementary exact-Unicode example is a separately reduced query-aware witness from the original frozen development suite. Its bundle checksum and successful observations are checked during the build. It is copied without altering the historic v1 benchmark counts.
